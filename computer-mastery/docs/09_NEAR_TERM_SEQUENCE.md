# Near-Term Challenge Sequence

This sequence is intentionally cumulative.

Challenge 01 already exists in full under `challenges/`.

## Challenge 01 — It Compiles, But It Won't Build

**Modes:** Investigate + Debug

Foundation:

```text
.cpp → .obj → symbols → linker → .exe
```

Primary concepts include translation units, compilation, object files, symbols, linking, unresolved externals, DUMPBIN, and the MSVC toolchain.

## Challenge 02 — What Did My Program Actually Do?

**Mode:** Investigate

Take the executable from Challenge 01 and make it perform observable OS work.

Use Process Monitor and related tools to investigate file access, DLL loading, process startup, unexpected OS activity, and what happens around the student's own code.

Bridge:

```text
Executable → Process → Operating System
```

## Challenge 03 — Build Your First Real Tool

**Mode:** Build

Internal-tools style assignment.

Build a command-line utility that inspects a directory and provides genuinely useful information.

The exact design should be chosen by the student.

Possible capabilities may emerge naturally: recursive traversal, file sizes, timestamps, extension summaries, largest files, filtering, and duplicate candidates.

Bridge:

```text
Process → Filesystem → Tooling
```

## Challenge 04 — Prove a File Hasn't Changed

**Modes:** Build + Defend

Add integrity verification to the file tooling.

This should naturally introduce hashes, integrity, manifests, SHA-256, and threat modeling.

Important question:

> If an attacker can modify both the file and the manifest, what protection does an ordinary hash actually provide?

Bridge:

```text
Filesystem → Integrity → Hashing → Security
```

## Challenge 05 — Who Is Running on My Computer?

**Modes:** Investigate + Build + Defend

Use Process Explorer first, then build a primitive process inspection utility.

Questions include what Windows exposes about processes, what information is useful, and what would matter during a suspected compromise.

Bridge:

```text
Processes → OS APIs → Defensive Tooling
```

## Challenge 06 — Two Programs Need to Talk

**Mode:** Build

Build networked software.

Introduce sockets, ports, TCP/UDP, client/server structure, byte order, and address resolution.

Bridge:

```text
Process → Socket → Network
```

## Challenge 07 — What Actually Went Across the Network?

**Mode:** Investigate

Use Wireshark to inspect traffic generated by Challenge 06.

Identify the handshake, addresses, ports, payload, and connection shutdown.

Bridge:

```text
Sockets → TCP/IP → Packets
```

## Challenge 08 — Anyone Can Read This

**Modes:** Build + Defend

The network traffic contains data that should not be visible to an observer.

Research the required security properties.

Do not jump directly to “encrypt it.” Ask whether the system needs confidentiality, integrity, authentication, replay protection, key exchange, and key storage.

Bridge:

```text
Packets → Threat Model → Cryptography → TLS Concepts
```

## Intent

By Challenge 08, earlier material should still matter.

The student should experience one growing system of knowledge rather than unrelated lessons.
